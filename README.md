# Nuxt Course Notes — static docs site

A documentation-style website that renders the 78 lesson notes in
[`topics/`](topics/) directly in the browser. No framework, no bundler, no
`node_modules` — just `index.html`, a bit of CSS/JS, and two small vendored
libraries, which is all GitHub Pages needs to serve it.

## How it works

- `index.html` is the single page shell: topbar, collapsible section sidebar,
  content area.
- `assets/js/manifest.js` lists every file in `topics/` with its title and
  course section, generated by [`scripts/generate-manifest.py`](scripts/generate-manifest.py).
  It is the only generated file — `topics/*.md` is never modified.
- `assets/js/app.js` is a tiny hash-based router (`#/05-what-is-nuxt`). On
  each navigation it `fetch()`es the matching file straight out of `topics/`
  and renders it with [marked](https://marked.js.org/) (markdown → HTML) and
  [highlight.js](https://highlightjs.org/) (code blocks), rewriting the
  lessons' own `NN-topic.md` cross-links into in-app navigation.
- `assets/vendor/` holds marked.js, highlight.js, and
  [github-markdown-css](https://github.com/sindresorhus/github-markdown-css),
  downloaded once and committed — no CDN calls at runtime, so the site also
  works offline or behind a restrictive CSP.
- Dark/light mode follows the OS by default and can be toggled (saved to
  `localStorage`).

Everything uses relative paths (`topics/...`, `assets/...`), so the site works
both at `https://<user>.github.io/` and `https://<user>.github.io/<repo>/`.

## Updating the lesson list

Add, remove, or rename a file in `topics/`, then regenerate the nav manifest:

```sh
python3 scripts/generate-manifest.py
```

This reads each file's first `# Heading` and its `Course section: N: Name`
line; it never writes into `topics/`.

## Running locally

Any static file server works, e.g.:

```sh
python3 -m http.server 8000
```

Then open <http://localhost:8000>. Opening `index.html` directly via
`file://` will **not** work — `fetch()` of local files is blocked by the
browser's CORS rules for the `file:` protocol, so a (tiny) local server is
required both for local testing and in production (which GitHub Pages
provides).

## Publishing with GitHub Pages

1. Push this repository to GitHub.
2. In the repo settings: **Settings → Pages → Build and deployment → Source**,
   choose **Deploy from a branch**, then pick the `main` branch and `/ (root)`
   folder.
3. GitHub serves the site as-is — no Actions workflow or build step needed.
   `.nojekyll` at the repo root disables Jekyll post-processing so every file
   (including everything under `topics/`) is served byte-for-byte.
