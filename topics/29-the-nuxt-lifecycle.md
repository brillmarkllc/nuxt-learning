# 29. The NUXT lifecycle

Course section: 3: The server

## What you will learn

Understand the request-to-page rendering flow.

In this lesson, **Lifecycle** is the main idea to recognize. Start with the example below, then use the vocabulary list whenever a term is unfamiliar.

## Key vocabulary

- **Lifecycle:** The stages an application or component passes through, from creation to cleanup.
- **SSR:** Server-side rendering: creating a page’s initial HTML on the server.
- **Hydration:** Vue connecting JavaScript behavior to HTML that the server already rendered.
- **Client:** The browser that displays the application and handles user interactions.
- **Server:** The environment that receives requests, accesses private data, and sends responses.

### 2. HTML response

Visit /example-html to inspect a plain HTML response. Normal Vue pages have their HTML generated by Nuxt instead.

**Where:** server/routes/example-html.get.js

```js
export default defineEventHandler((event) => {

```

### 3. Hydration

The initial count is the same on server and client; onMounted runs only after browser mounting.

**Where:** app/pages/lifecycle.vue

```vue
<script setup>
const count = ref(0)
onMounted(() => console.log('Mounted in the browser'))
</script>
<template><button @click="count++">{{ count }}</button></template>
```

### 4. Subsequent navigation

Route updates may reuse the component, so watch the value that matters rather than assuming setup reruns.

**Where:** app/pages/lifecycle.vue — script setup

```js
const route = useRoute()
watch(() => route.query.tab, tab => console.log('New tab:', tab))
```

## Remember

- Code used during rendering can execute in both environments.

## Best practices and edge cases

- Universal rendering produces HTML on the server, then hydrates it in the browser. Initial markup must agree in both environments.
- A static deployment serves generated files and cannot execute your Nuxt API handlers. Keep a server deployment or a separately hosted backend for dynamic writes.
- Pre-rendered data is captured during the build. Keep private or frequently changing user data out of shared generated output.
- Use routeRules to choose rendering behavior for specific paths. Verify dynamic routes and direct page reloads in the production build.
