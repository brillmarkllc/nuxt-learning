# 27. 404 Page

Course section: 2: The Pages

**404** means the requested page or item was not found. A useful error screen explains the problem and gives the visitor a way back.

**Additional working example:** Create `app/error.vue`, beside `app/app.vue`:

```vue
<script setup>
const props = defineProps({ error: Object })
const code = computed(() => props.error?.status || props.error?.statusCode || 500)
function goHome() {
  return clearError({ redirect: '/' })
}
</script>

<template>
  <main>
    <h1>{{ code === 404 ? 'Page not found' : 'Something went wrong' }}</h1>
    <p>Try returning to the home page.</p>
    <button @click="goHome">Go home</button>
  </main>
</template>
```

Visit `/a-page-that-does-not-exist`. You should see the missing-page message. Click “Go home” to clear the error and return to the existing home page.

`error` is information Nuxt passes to this component. `?.` reads a property only when the object exists. The status fallback also supports earlier Nuxt 4 examples that expose `statusCode`; the current documentation uses `status`.

## Report a missing item deliberately

For a small separate test, create `app/pages/missing-book.vue`:

```vue
<script setup>
throw createError({ status: 404, statusText: 'Book not found', fatal: true })
</script>

<template>
  <main>Book details</main>
</template>
```

Opening `/missing-book` should show the error screen. `throw` stops normal processing. `fatal: true` also requests the full error screen during browser navigation. In a real book page, only throw this after checking that the requested book is absent.

The error screen handles more than 404 errors. Keep it simple, avoid displaying private error details, and do not depend on a plugin that may itself have failed.
