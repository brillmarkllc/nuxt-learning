# 27. 404 Page

Course section: 2: The Pages

## What you will learn

Replace the default error display with useful UI.

In this lesson, **404** is the main idea to recognize. Start with the example below, then use the vocabulary list whenever a term is unfamiliar.

## Key vocabulary

- **404:** The HTTP status indicating that the requested resource was not found.
- **HTTP status:** A response number describing an outcome, such as 200 for success or 404 for missing content.
- **createError:** A helper for creating an error with information such as an HTTP status.
- **clearError:** A Nuxt helper that clears the active application error, optionally redirecting afterward.

## What this topic includes

Create app/error.vue for the application error screen. The snippets below show alternatives or parts of that file.

**How to use the examples:** Each numbered subsection covers one listed subtopic. Blocks labeled “script setup”, “inside”, or “fragment” belong in the indicated surrounding component or handler. Alternative versions replace one another; do not paste every block into a single file.

### 1. Error.vue

The error page receives an error prop, including its status code.

**Where:** app/error.vue

```vue
<script setup>
defineProps({ error: Object })
</script>
<template><main><h1>{{ error?.statusCode || 500 }}</h1><p>We could not open this page.</p></main></template>
```

### 2. Error details

Throw a controlled 404 when a requested record does not exist.

**Where:** app/pages/missing.vue — script setup

```js
throw createError({ statusCode: 404, statusMessage: 'Event not found' })
```

### 3. Recovery navigation

Clear the current error and redirect to a known safe route when the user clicks the recovery button.

**Where:** app/error.vue

```vue
<script setup>
defineProps({ error: Object })
const goHome = () => clearError({ redirect: '/' })
</script>
<template><main><h1>{{ error?.statusCode }}</h1><button @click="goHome">Go home</button></main></template>
```
## Simple example

Show “Page not found” and a button that clears the error and returns home.

## Remember

- The error component can handle errors beyond 404; inspect the status.

## Best practices and edge cases

- Use createError for errors with a status code and safe public message. Distinguish a missing record from an unexpected server failure.
- An error page is a separate rendering flow. Avoid assuming every plugin or application dependency remains available after an initialization failure.
- Use clearError with a redirect for a recovery button and verify that the destination itself does not repeat the same failure.

## Try it yourself

Rebuild the example above, then test it with a direct page reload and navigation from another page. Check both the browser console and server terminal for errors.
